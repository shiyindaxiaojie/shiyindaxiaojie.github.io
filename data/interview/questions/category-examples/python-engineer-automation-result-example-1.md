::interviewer::
讲一次 Python 自动化真正减少人工工作的改造。

::candidate level="core"::
先还原人工流程的频率、耗时和错误点，再讲自动化覆盖了哪些步骤、异常时怎样接管。结果用工单、执行时长、失败率和人工介入次数衡量，不把一次脚本运行成功等同流程完成。

::interviewer::
这段回答怎么用真实材料支撑，而不是只靠口述？

::candidate level="deep"::
执行日志、前后状态校验、失败分类、人工接管和用户采用率共同构成证据；还要统计脚本维护时间。

::interviewer::
自动化成果这段经历还有什么代价或没解决的问题？

::candidate::
自动化不该掩盖不稳定流程。变化频繁且规则未收敛时，先标准化输入和责任边界，再写更多代码。
